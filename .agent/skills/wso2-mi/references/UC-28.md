# UC-28

## 1. Mô tả nghiệp vụ
Use Case UC-28 thuộc domain **receiving**.
Mô tả đầy đủ luồng xử lý nghiệp vụ, điều kiện kích hoạt và ràng buộc hệ thống.

---

## 2. Actor
- Hệ thống ngoài (External System)
- API Gateway
- Core Processing Service
- Database

---

## 3. Endpoint

| Method | URL |
|--------|-----|
| POST/GET | /api/v1/receiving/uc-28 |

---

## 4. Request Schema

| Field | Type | Required | Rule |
|-------|------|----------|------|
| requestId | string | Yes | Unique toàn hệ thống |
| payload | object | Yes | Theo cấu trúc nghiệp vụ |
| signature | object | Conditional | Bắt buộc nếu có yêu cầu pháp lý |

### Example Request
```json
{
  "requestId": "REQ_28_001",
  "payload": {},
  "signature": {}
}
```

---

## 5. Business Validation Rules

1. requestId không được trùng.
2. Dữ liệu phải hợp lệ theo schema.
3. Nếu có chữ ký số → phải verify.
4. Không được bypass trạng thái hệ thống.

---

## 6. Processing Flow

1. Receive request
2. Validate schema
3. Apply business rule
4. Persist database
5. Write audit log
6. Return response

---

## 7. Response Schema

| Field | Type | Description |
|-------|------|------------|
| status | string | SUCCESS / FAILED |
| code | string | Mã xử lý |
| message | string | Mô tả |
| data | object | Payload trả về |

### Example Response
```json
{
  "status": "SUCCESS",
  "code": "00",
  "message": "Processed successfully",
  "data": {}
}
```

---

## 8. Error Handling

| Code | Meaning |
|------|--------|
| 400 | Bad Request |
| 401 | Unauthorized |
| 409 | Duplicate request |
| 500 | System error |

---

## 9. Audit & Logging

Bắt buộc ghi nhận:
- requestId
- actor
- timestamp
- IP address
- business result
- errorCode (nếu có)

---

## 10. Data Invariants

- requestId immutable
- Không được chỉnh sửa dữ liệu lịch sử
- Log không được xóa

---

## 11. Agent Reasoning Notes (Instruction-Aware)

Khi AI generate code:
- Controller chỉ validate input cơ bản
- Service xử lý toàn bộ business logic
- Repository không chứa validation logic
- Phải enforce unique index ở DB level
- Không trả dữ liệu nhạy cảm ngoài tài liệu quy định

---

## 12. Embedding Chunk Strategy

Chunk đề xuất:

- Chunk A: Metadata + Endpoint
- Chunk B: Validation + Rules
- Chunk C: Processing Flow
- Chunk D: Response + Error Codes
- Chunk E: Audit + Invariants

Mỗi chunk tối đa 800–1200 tokens để tối ưu retrieval.
