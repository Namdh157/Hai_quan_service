# UC-26. Định tuyến thông điệp

## 1. Thông tin chung

| Thuộc tính | Giá trị |
| --- | --- |
| Tên API | Định tuyến thông điệp |
| Mã API | API-ROUTING-DISPATCH |
| Use Case | UC-26 |
| Phương thức | POST |
| Endpoint | `/api/v1/routing/dispatch` |

## 2. Mục đích nghiệp vụ
Tự động xác định và chuyển thông điệp/hồ sơ đến phân hệ nghiệp vụ phù hợp để xử lý tiếp theo.

## 3. Thời điểm & điều kiện gọi
- Sau khi hồ sơ được tiếp nhận và xác thực chữ ký số thành công (UC-25)
- Thông điệp đã được kiểm tra cấu trúc và ràng buộc dữ liệu

## 4. Request Body

| Field | Kiểu | Bắt buộc | Quy tắc nghiệp vụ |
| --- | --- | --- | --- |
| `requestId` | string | Có | Duy nhất |
| `registrationId` | string | Có | Hồ sơ hợp lệ |
| `procedureCode` | string | Có | Xác định tuyến |
| `payload` | xml | Có | Nội dung hồ sơ |

**Ví dụ Request (XML):**
```xml
<RoutingDispatchRequest>
  <requestId>REQ_20250201001</requestId>
  <registrationId>HS000123</registrationId>
  <procedureCode>HQ01</procedureCode>
  <payload>
    <!-- Nội dung hồ sơ XML -->
  </payload>
</RoutingDispatchRequest>
```

## 5. Quy tắc nghiệp vụ
- Mỗi `procedureCode` phải map duy nhất 1 phân hệ nghiệp vụ.
- Nếu không xác định được tuyến → trả lỗi, không retry tự động.

## 6. Response thành công (200)

**Ví dụ Response (XML):**
```xml
<RoutingDispatchResponse>
  <routed>true</routed>
  <targetSystem>NGHIEP_VU_HQ</targetSystem>
  <routedAt>2025-02-01T09:20:00</routedAt>
</RoutingDispatchResponse>
```
