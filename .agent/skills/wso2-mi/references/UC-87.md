# UC-87. Tra cứu tình trạng hoạt động hệ thống (System Health Check)

## 1. Thông tin chung

| Thuộc tính | Giá trị |
| --- | --- |
| Tên API | Tra cứu tình trạng hoạt động hệ thống |
| Mã API | API-MONITOR-HEALTH |
| Use Case | UC-87 |
| Phương thức | GET |
| Endpoint | `/api/v1/monitoring/health` |

## 2. Mục đích nghiệp vụ
Cung cấp thông tin tổng thể về tình trạng hoạt động của hệ thống nhằm:
- Giám sát thời gian hoạt động (uptime).
- Kiểm tra trạng thái khả dụng của các dịch vụ thành phần.
- Phục vụ dashboard vận hành và giám sát tập trung.

## 3. Thời điểm & điều kiện gọi
- Được gọi định kỳ bởi các hệ thống giám sát.
- Tài khoản Quản trị hệ thống (QTHT) hoặc hệ thống giám sát được cấp phép truy cập.

## 4. Request Header

| Tên | Kiểu | Bắt buộc | Mô tả |
| --- | --- | --- | --- |
| `Authorization` | string | Có | Token hợp lệ |

## 5. Response thành công (200 OK) (XML)

```xml
<response>
  <status>UP</status>
  <timestamp>2025-02-01T10:00:00</timestamp>
  <services>
    <service>
      <serviceName>DATABASE</serviceName>
      <status>UP</status>
    </service>
    <service>
      <serviceName>ROUTING_ENGINE</serviceName>
      <status>UP</status>
    </service>
  </services>
</response>
```

## 6. Quy tắc nghiệp vụ
- **Trạng thái (Status)**: Các giá trị hợp lệ bao gồm `UP`, `DEGRADED`, `DOWN`.
- **Logic tổng quát**: Nếu bất kỳ dịch vụ thành phần nào ở trạng thái `DOWN`, trạng thái tổng thể của hệ thống phải được đánh dấu là `DEGRADED` hoặc `DOWN`.
- **Bảo mật**: Tuyệt đối không tiết lộ thông tin cấu hình nhạy cảm (như chuỗi kết nối, mật khẩu) trong phản hồi API.

## 7. Logging & Audit
- Hệ thống phải ghi log mỗi lần API này được truy vấn, bao gồm thời điểm và tài khoản thực hiện.
- Không ghi nhật ký chi tiết về cấu trúc nội bộ của cơ sở dữ liệu.
