# UC-82. Tra cứu và cập nhật giới hạn hệ thống

## 1. Thông tin chung

| Thuộc tính | Giá trị |
| --- | --- |
| Tên API | Tra cứu và cập nhật giới hạn |
| Mã API | API-LIMIT-SEARCH |
| Use Case | UC-82 |
| Phương thức | GET / PUT |
| Endpoint | `/api/v1/limits` |

## 2. Mục đích nghiệp vụ
Cho phép Quản trị hệ thống (QTHT) tra cứu các cấu hình giới hạn hiện tại và điều chỉnh khi cần thiết.

## 3. Request – Query Parameters (GET)

| Tên | Kiểu | Bắt buộc | Mô tả |
| --- | --- | --- | --- |
| `limitType` | string | Không | Lọc theo loại giới hạn |
| `target` | string | Không | Đối tượng áp dụng |

## 4. Response Tra cứu (GET) (XML)

```xml
<response>
  <items>
    <item>
      <limitId>LIMIT001</limitId>
      <limitType>API_RATE</limitType>
      <target>ENTERPRISE</target>
      <maxValue>1000</maxValue>
      <timeWindow>1H</timeWindow>
      <actionOnExceed>REJECT</actionOnExceed>
      <status>ACTIVE</status>
    </item>
  </items>
</response>
```

## 5. Cập nhật giới hạn (PUT)
**Endpoint:** `/api/v1/limits/{limitId}` *(Thực hiện cập nhật cho bản ghi cụ thể)*

**Request Body (XML):**
```xml
<request>
  <maxValue>1500</maxValue>
  <actionOnExceed>THROTTLE</actionOnExceed>
</request>
```

## 6. Quy tắc nghiệp vụ
- **Phạm vi cập nhật**: Chỉ cho cập nhật ngưỡng (`maxValue`) và hành động khi vượt ngưỡng (`actionOnExceed`).
- **Ràng buộc**: Không cho thay đổi `limitType` và `target` của một giới hạn đã tạo.
- **Audit Log**: Mọi cập nhật phải ghi log chi tiết:
  - Giá trị cũ → giá trị mới.
  - Người thực hiện.
  - Thời điểm.
